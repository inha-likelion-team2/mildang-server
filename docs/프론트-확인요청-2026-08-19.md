## ① 하루 넘기기 — 백엔드 버그였습니다 (수정 완료)

제보해주신 게 맞았습니다. 원인이 두 겹이었습니다.

**(1) 완주 전이를 안 했습니다.** `POST /demo/advance-day`가 날짜만 옮기고 상태는 그대로 뒀습니다. 그래서 마지막 날을 넘겨도 응답이 이랬습니다.

```json
{ "dayIndex": 7, "status": "ACTIVE" }   // ← 넘겼는데 그대로. «안 넘어간다»로 보임
```

실제 완주 전이는 그다음 `GET /challenges/current` 호출에서야 일어났습니다.

**(2) 완주 후엔 404였습니다.** 조회 대상이 `ONBOARDING`·`ACTIVE`뿐이라, 한 번 완주하면 그 뒤로 「하루 넘기기」가 영영 404를 냈습니다. 시연 중에 버튼이 죽습니다.

### 이제 이렇게 옵니다

```json
POST /v1/demo/advance-day   { "days": 1 }

{
  "mocked": true,
  "challengeId": "chl_...",     // ← 추가됨
  "dayIndex": 7,
  "status": "COMPLETED",
  "completed": true             // ← 추가됨
}
```

`completed`가 `true`가 되는 순간 그 자리에서 리포트로 보내시면 됩니다. `challengeId`도 같이 오니 `GET /challenges/{id}/report`를 바로 부를 수 있습니다.

### 배포본에서 확인한 결과

```
하루 넘기기 #1 → dayIndex=5  ACTIVE     completed=false
하루 넘기기 #2 → dayIndex=6  ACTIVE     completed=false
하루 넘기기 #3 → dayIndex=7  ACTIVE     completed=false   ← 마지막 날은 아직 진행 중
하루 넘기기 #4 → dayIndex=7  COMPLETED  completed=true    ← 여기서 완주
하루 넘기기 #5 → dayIndex=7  COMPLETED  completed=true    ← 더 눌러도 404 안 남
```

**마지막 날(7일차)은 계속 `ACTIVE`입니다.** 그날도 기록하고 밀당해야 하니까요. 하루가 더 지나야 완주입니다.

> 배포 확인: `GET /v1/health`의 `codeVersion`이 **`2026-08-19-advance-day-fix`**면 반영된 것입니다.

## ② 예산 화면 — 문구와 값이 서로 다른 걸 가리킵니다

### 무엇이 어긋났나

**`src/screen/Budget.jsx` 50행** — 문구가 「1주」로 하드코딩돼 있습니다.

```jsx
<h1 id="budget-title"><span>1주 예산을</span><span>설정해볼까요?</span></h1>
```

**같은 파일 32행** — 그런데 보여주는 값은 **기간 총액**입니다.

```js
const budgetValue = Number(selected?.totalBudget ?? selected?.budget ?? 0)
```

4주 챌린지면 `totalBudget = 주간값 × 4`입니다. 주 500이면 화면에는 **2000**이 뜨는데 문구는 「1주 예산」이라, 「1주에 2000밀」로 읽힙니다.

| 필드 | 뜻 | W1 | W2 | W4 |
| --- | --- | --- | --- | --- |
| `budget` | **주간값** | 225 | 225 | 225 |
| `totalBudget` | 기간 총액 | 225 | 450 | 900 |

W1에서는 곱수가 1이라 둘이 같아서 눈에 안 띄고, **W2·W4에서 처음 드러납니다.**

### 권장 수정

말씀하신 대로 **주 표기를 빼는 쪽**이 가장 간단하고 안전합니다.

```jsx
// 50행
<h1 id="budget-title"><span>예산을</span><span>설정해볼까요?</span></h1>

// 32행 — 서버에 보낼 값과 같은 «주간값»을 보여준다
const budgetValue = Number(selected?.budget ?? 0)
```

**서버에 보내는 값은 어차피 주간값**이라, 화면에도 주간값을 띄우는 게 자연스럽습니다. 총액은 예산 설정을 마친 뒤 `POST /budget` 응답의 `budget`(총액)으로 보여주시면 됩니다.

기간별로 문구를 바꾸고 싶으시면 `selectedPlan.period`를 이미 들고 계시니 이렇게 하시면 됩니다.

```jsx
const label = { W1: '1주', W2: '2주', W4: '4주' }[period] ?? ''
<h1><span>{label} 예산을</span><span>설정해볼까요?</span></h1>
```

> ⚠ 이 화면은 슬라이더 관련해서도 손볼 곳이 있습니다 — `estimate.options` 3개 대신 `estimate.slider`(min~max, step 5)를 쓰셔야 연속값이 됩니다. 자세한 건 `API-변경-2026-08-19.md` ②-B를 봐주세요.

## ③ 리포트 스크롤 — 원인이 3개입니다

「스크롤이 안 돼서 공유 버튼과 뒤로가기가 안 보인다」를 뜯어보니 서로 다른 원인 셋이 겹쳐 있었습니다.

### (a) 전역 `body`가 스크롤을 막고 있습니다 ← 가장 큰 원인

```css
/* src/css/Onboarding1.css:30  그리고  src/css/StartScreen.css:21 — 두 곳에 중복 정의 */
body {
  min-width: 320px;
  min-height: 100dvh;
  display: grid;
  place-items: center;
  overflow: hidden;      /* ← 페이지 전체 스크롤 차단 */
  background: #f5f5f5;
}
```

화면별 CSS 파일 안에 들어 있지만 **CSS는 전역**입니다. Vite가 전부 한 번에 로드하므로 이 규칙이 **모든 화면**에 걸립니다. 결제 화면 스크롤이 안 됐던 것도 같은 뿌리입니다.

내용이 화면보다 길어지는 순간 넘친 부분에 **접근할 방법이 없어집니다.**

**권장**: 전역 규칙을 화면별 파일에서 빼내 공용 파일(예: `src/css/base.css`) 하나로 옮기고, `overflow: hidden`을 없애거나 최소한 세로는 열어주세요.

```css
body {
  min-width: 320px;
  min-height: 100dvh;
  display: grid;
  place-items: center;
  overflow-x: hidden;    /* 가로만 막고 */
  background: #f5f5f5;
}
```

### (b) 리포트 카드 자체가 잘립니다

```css
/* src/css/7_completeReport.css:49~53 */
.report-card {
  position: absolute;
  top: 217px;
  width: 320px;
  height: 500px;        /* ← 높이 고정 */
  overflow: hidden;     /* ← 넘치면 그냥 잘림 */
}
```

카드 안 내용이 500px을 넘으면 **잘려서 보이지 않습니다.** 스크롤도 안 됩니다.

**권장**: 높이를 내용에 맡기거나(`height: auto` + `min-height: 500px`), 카드 안에서 스크롤되게 하세요.

```css
.report-card {
  height: auto;
  min-height: 500px;
  overflow: visible;
}
```

⚠ 공유 카드(PNG)로 캡처하는 요소라면 **캡처 시점의 높이**도 같이 확인해주세요. 잘린 채로 캡처되면 공유 이미지도 잘립니다.

### (c) 뒤로가기 버튼은 「안 보이는」 게 아니라 **없습니다**

`src/screen/7_completeReport.jsx`를 검색해보면 뒤로가기 관련 코드가 **0건**입니다. 화면에 버튼이 하나뿐입니다.

```jsx
function CompleteReport({ error, isLoading = false, onShare, report, shareCard }) {
  // ... onBack 프로퍼티 자체가 없음
  <button className="complete-report__share" onClick={onShare}>스토리에 공유하기</button>
}
```

CSS로 해결될 문제가 아니라 **컴포넌트에 버튼을 추가**하셔야 합니다. 다른 화면들처럼 `onBack` 프로퍼티를 받아서 `App.jsx`에서 넘겨주는 형태가 맞겠습니다.

> 참고: 완주 상태에서 **메인보드로 돌아가는 건 서버가 막지 않습니다.** `GET /challenges/current`가 200 + `status: "COMPLETED"`로 계속 응답합니다. 다만 그 상태에서 **기록·밀당·체크인 같은 쓰기는 404**이니, 돌아간 화면에서는 기록 버튼을 비활성화해주세요.

## 덤 — 재발할 곳 두 군데

### 결제 화면 스크롤은 601px 이상에서 다시 막힙니다

`src/css/Onboarding2_1.css`에서 스크롤은 **`@media (max-width: 600px)` 안에서만** 켜집니다.

```css
.payment-screen {
  aspect-ratio: 402 / 874;
  overflow: hidden;          /* 기본은 막힘 */
}

@media (max-width: 600px) {
  .payment-screen {
    height: 100dvh;
    aspect-ratio: auto;
    overflow-y: auto;        /* 여기서만 켜짐 */
  }
}
```

폰에서는 되지만 **노트북 브라우저·태블릿·가로 화면에서는 잘립니다.** 심사위원이 노트북으로 열면 다시 나타납니다. (a)의 `body { overflow: hidden }`을 걷어내면 대부분 같이 해결됩니다.

### `.payment-screen` 클래스가 두 파일에 중복 정의돼 있습니다

`Onboarding2_1.css`(2주)와 `Onboarding2_2.css`(4주)가 **둘 다 `.payment-screen`을 정의**합니다. 두 파일은 딱 한 줄 빼고 완전히 같습니다.

```
272c272
< .payment-screen--two-week .payment-screen__submit {
---
> .payment-screen--four-week .payment-screen__submit {
```

CSS는 전역이라 **나중에 로드된 쪽이 이깁니다.** 지금은 내용이 같아서 티가 안 나지만, 한쪽만 고치는 순간 「2주만 고쳤는데 4주도 바뀌었다」 같은 일이 생깁니다. 두 파일을 하나로 합치고 `--two-week` / `--four-week` 수식자로만 구분하시는 게 맞습니다.
