## 1. 예산(밀가루 양) 부족 문제

### 진단

- 참조 스케일이 **칼국수 1그릇 = 80**을 앵커로 하는데, 기존 설문 가중치는 명세 §3.3 예시(→100→75/85/95)에 맞춰 역산되어 있었음.
- 결과: 기본 설문 기준 **주 예산 70** — 라면(80) 한 번에 예산 전체가 소진.
- "줄이며 버티는 흥정 게임"이 아니라 사실상 "끊기"가 되어 **제품 컨셉(끊지 마세요, 밀당하세요)과 정면 충돌**. 초과가 기본 상태가 되면 흥정할 동기도, 게이지를 지킬 재미도 없음.

### 반영 완료 ✅ (ed02fb5)

가중치를 **참조 스케일 × 주간 빈도 중앙값**으로 재산정:

| 항목 | 0–1회 | 2–3회 | 4회+ |
|------|------|------|------|
| 면류 | 30 | 150 | 270 |
| 빵류 | 25 | 110 | 200 |
| 과자·간식 | 10 | 50 | 90 |

- 기본 설문(면 2–3 · 빵 0–1 · 간식 2–3): 추정 225 → **주 190** (AS_IS −15%)
- 라면 2번(160)을 먹어도 30이 남고, 흥정으로 반 줄이면 김밥·간식 여유가 생기는 스케일 — "아껴서 버티는" 긴장이 성립.
- 컷률(HARD −25% / AS_IS −15% / EASY −5%)과 옵션 구조는 명세 그대로 유지.

### 남은 결정 📋

1. **명세 §3.3 예시 갱신** — 현재 명세 예시(100→75/85/95)와 구현이 다름. 명세를 새 산식 기준으로 개정 요청.
2. **§14.5 심사위원 시드 스케일** — judge-02(총 85), W4(총 340) 등 시드는 명세값 그대로 둠. 신규 온보딩(주 190)과 스케일이 달라 심사위원이 시드 계정과 새 계정을 오가면 어색할 수 있음. **시드도 같은 배율(약 ×2.2)로 상향할지** 결정 필요 — 백엔드는 결정만 나오면 즉시 반영 가능.
3. (선택) 예산 하한선 — 설문을 전부 0–1로 답해도 최소 "라면 1번 + α"(예: 주 100)는 보장할지. 현재 최저 조합은 65→55.

## 2. 완주 리포트 부실 문제

### 진단

- **실 AI를 붙여도 리포트는 거의 안 달라짐** — AI가 만드는 건 발견(finding) 헤드라인 문구 한 줄뿐. 통계·하이라이트·CTA는 전부 백엔드 계산이라 지금 보이는 것이 곧 최종 품질.
- 근본 원인은 **명세 §9.1 구성 자체가 단출**한 것: 통계 3칸 + 발견 1개 + 흥정 하이라이트 1줄이 전부.
- 사전 페르소나 평가(16명)에서도 **"결제 전환의 병목 = 리포트 품질"** 이 최상위 리스크였음. 리포트는 유료 재도전(재대결)과 SNS 공유의 근거이자 데모 시연의 클라이맥스 — 여기가 약하면 수익 모델 서사가 무너짐.
- 데이터가 적으면(기록 2~3건) 더 얄팍해 보임 — 표본 부족 상태의 표현도 설계 필요.

### 개선안 (우선순위순)

#### 2-1. 백엔드 보유 데이터만으로 가능 🔧 — 명세 확장 합의만 되면 즉시 구현

| # | 제안 | 내용 | 근거 데이터 |
|---|------|------|------------|
| a | **일별 소비 그래프** | 7일(14/28일) 막대·스파크라인 + 페이스 라인. "언제 무너졌고 언제 지켰는지"가 한눈에 | items 기록 시각(05:00 경계) — 이미 보유 |
| b | **요일·시간대 패턴** | "초과의 80%가 금요일 저녁" — 대시보드 팁과 동일 신호를 리포트에서 회고로 재사용 | 최다 소비 계산에 쓰는 데이터 그대로 |
| c | **흥정 스토리 확장** | 절감 총액을 "라면 N번 값" 환산, 세션별 절감 목록(원래→합의), 최장 승부(턴 수) 소개 | haggle_sessions — 이미 보유 |
| d | **체크인 상관 3종 전부 표시** | 현재 대표 발견 1개만 노출 → 더부룩함·피부·낮 졸림 3지표를 미니 카드로 (계산 불가 지표는 "다음 판에 알 수 있어요"로 재도전 훅) | checkins — 이미 보유 |
| e | **"덜 깊어진 날" 카운트** | 초과일도 톤 규칙에 맞게 자산화: "18일 중 15일을 예산 안에서" | items + budget |
| f | **재대결 CTA 근거 문구** | "이번 판 페이스면 HARD도 해볼 만해요" — suggestedBudget에 이유 붙이기 | pace 계산 재사용 |

#### 2-2. AI 계약 추가 필요 🤝

| # | 제안 | 내용 |
|---|------|------|
| g | **밀당이의 총평 한 문단** | stats+finding+하이라이트를 입력으로 4~6문장 서사 생성 (`/internal/report-summary` 신설). 기존 게이트(금지 어휘·90자 규칙은 문단용으로 완화)·재시도 1회·폴백 템플릿 패턴 동일 적용. "숫자 나열"을 "내 얘기"로 바꾸는 가장 효율적인 한 방 |
| h | 발견 문구 다양화 | 현재 폴백·실 AI 모두 한 가지 문형 — 조건·비율 크기별 문형 변주 프롬프트 |

#### 2-3. 표본 부족 상태의 설계 📋

- 기록 N건 미만·체크인 M일 미만이면 발견 대신 **"다음 판을 위한 밑그림"** 섹션(이번에 쌓인 것 + 다음에 알 수 있는 것)으로 전환 — 빈약함을 재도전 유도로 반전.
- 공유 카드도 발견 없을 때의 대체 카피 확정 필요 (현재: "한 판을 끝까지 버텼습니다").

### 제안 요약

- **지금 바로 가능한 최소 패키지**: a(그래프) + c(흥정 스토리) + d(상관 3종) — 백엔드 단독, API 응답 확장만으로 리포트 밀도가 체감 수준으로 달라짐.
- **가성비 최고 한 방**: g(AI 총평) — AI팀과 계약 1개 추가.
- 전부 **명세 §9.1 개정이 전제**이므로 기획 확정 후 착수. 백엔드 구현 리드타임은 2-1 전체 기준 반나절 내.
